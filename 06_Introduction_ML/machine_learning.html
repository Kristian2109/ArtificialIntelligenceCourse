01 / Foundations

Foundations of machine learning

  • Rule-based programming: follow instructions we specify.
  • Machine learning: fit a model from examples, then apply it to new inputs.
  • Generalization: do well beyond the examples used for training.

Inductive learning: from examples to patterns

After seeing many deliveries, a model may learn how distance and traffic relate to travel time. This is induction. The pattern is an informed guess; another route can still surprise it.

Completed deliveries→General relationship

Deductive reasoning: applying general rules

“Every route over 10 km needs a long-distance fee; this route is 12 km; add the fee.” This is deduction: applying a given rule.

Fee rule + 12 km route→Apply the fee

Training does not continue automatically after release. A deployed model usually stays fixed until we deliberately update it.

02 / Data and preprocessing

Data representation and preprocessing

  • Dataset: a collection of examples; here, one row is one completed delivery.
  • Feature: an input characteristic, such as distance or rain.
  • Target: the value we want to predict, such as delivery time.

Example dataset: delivery-time prediction

X holds the input features; y holds the target. Three input columns means three dimensions. A model is a learned mapping: ŷ = f(X). The hat marks a prediction.
01Clean
  • Missing values: a missing distance can be filled with the training-set median, for example 4.5 km.
  • Invalid values: flag −3 km and check the source; do not silently turn it into a valid distance.
  • Consistent units: convert 2,500 m → 2.5 km. Use the same unit across records.
  • Consistent categories: map Yes, Y, and yes to one rain value.
  • Duplicates and outliers: remove confirmed duplicate records. Investigate an unusually long delivery before deciding it is an error.
02Integrate
  • Join related records: match the route file and parcel file using the same delivery ID.
  • Example: delivery D43 has 5 km in one file and 2,000 g in another. The joined row contains both features.
  • Missing matches: if D44 has no parcel record, flag the missing information rather than silently losing the delivery.
  • Check the result: unexpected extra rows may mean an ID appeared several times. Confirm what one joined row represents.
03Encode & construct
  • Binary encoding: represent the rain flag as No → 0 and Yes → 1.
  • One-hot encoding: with columns [bike, van], encode a bike as [1, 0] and a van as [0, 1].
  • Construct a useful feature: if rush hour is defined as 17:00–19:00, a departure at 18:00 → rush_hour = 1.
  • Extract date information: turn a departure date into its day of the week. Use only information available before the delivery begins.
04Scale
  • Min–max example: with a training distance range of 0–10 km, 5 km → (5 − 0) / (10 − 0) = 0.5.
  • Another unit: with a training mass range of 0–5,000 g, 2,500 g → 0.5. Large gram values no longer dominate merely because of their units.
  • Standardization example: if the training mean is 5 km and standard deviation is 2 km, 9 km → (9 − 5) / 2 = 2.
  • Apply consistently: learn the ranges, means, and standard deviations from training data; reuse them for validation, test, and future deliveries.
05Aggregate & discretize
  • Aggregation: three completed deliveries lasting 10, 20, and 30 minutes can become a daily count of 3 and mean duration of 20 minutes.
  • Discretization: replace exact distances with bands: short < 3 km, medium 3–<7 km, and long ≥ 7 km.
  • Example: 2 km → short; 8 km → long. Distances of 3.1 km and 6.9 km both become “medium.”
  • What is lost: a mean hides individual delays, and a band hides exact distances. Historical summaries used as inputs must contain only earlier deliveries.
06Reduce
  • Select features: keep an arbitrary delivery ID for joining files, but leave it out of the predictors when it carries no useful pattern.
  • Remove redundancy: if distance_m is just distance_km × 1,000, keep one version.
  • Sample rows: use a representative subset, such as 10,000 of 100,000 deliveries, while checking that important routes and conditions remain represented.
  • PCA example: three correlated parcel dimensions—length, width, and height—can be represented by two learned components. These are combinations of the original features; check how much information is retained.

Feature scaling and nearest-neighbor selection

Try both scales

Distance is in km; parcel mass is in grams. Without scaling, grams dominate Euclidean distance. Scaling changes what “near” means.

Training ranges: 0–10 km and 0–5,000 g. The axes change units too, so positions stay fixed. Compare the calculated distances, not line lengths on screen.

Only use information available at prediction time. “Actual arrival time” would reveal the target. Split the data first, then learn imputation values, scaling statistics, and PCA from the training portion.
03 / Model evaluation

Training, validation, and test evaluation

A low error on familiar examples is encouraging, but it does not tell us how the model will handle a new delivery. Give each part of the dataset a clear role.

60%TrainingLearn the model's parameters.
20%ValidationChoose models and settings.
20%TestEvaluate the final choice.
  • The proportions are an example, not a rule.
  • For forecasting, keep future data after past data.
  • Keep the same person or delivery out of multiple splits. Match the split to how the model will be used.

Five-fold cross-validation

Select a round
used for trainingheld out for validation (gold)
  • Divide: split the development data into five parts.
  • Repeat: fit a fresh model on four parts; validate on the remaining part.
  • Compare: average the five validation scores to choose settings.

Fit preprocessing inside each fold. The test set stays outside this process. Once settings are chosen, refit on the development data and evaluate on the test set.

Regression tasks and numerical error metrics

Regression: predict a numeric quantity, such as 27.5 minutes. Mean squared error averages squared prediction errors; mean absolute error is in the target's units.

Classification tasks and accuracy

Classification: predict a discrete class, such as “late” or “on time.” Accuracy is the fraction correct. If only 5% of deliveries are late, always predicting “on time” gets 95% accuracy and misses every late delivery.

The test set is a final check. Repeatedly changing a model after seeing its test score turns that set into another validation set.
04 / Complexity and generalization

Model complexity and generalization

A model can be too rigid to capture a relationship, or so flexible that it follows accidental details. Complexity describes the patterns a model can represent; parameter count is only one rough indicator.

TOO RIGID

Underfitting and prediction bias

  • Underfitting: strong restrictions can make the model miss a real relationship.
  • Bias: systematic error in the average prediction across training samples.
TOO SENSITIVE

Overfitting and prediction variance

  • Overfitting: a close training fit that performs worse on new examples.
  • Variance: how much predictions change when the training sample changes.
UNPREDICTABLE DETAIL

Noise and unexplained variation

Some variation is not explained by the available inputs: a traffic light, a recording error, or an unmeasured delay. Fitting it more closely may not help.

The practical trade-off: increasing flexibility often lowers bias and raises variance. It is a useful tendency, not a law for every model. Use validation to choose complexity; the lowest training error is not the goal.
05 / Supervised algorithms

Supervised learning algorithms

Linear regression predicts a numeric target, such as delivery time, using a weighted sum of the inputs plus an intercept. For classification, the target is a category, such as “late” or “on time.” The methods below illustrate different approaches to supervised prediction.

Logistic regression

Classification
  • Score: compute a weighted sum, z = w·x + b.
  • Probability: the sigmoid maps that score to a value between 0 and 1.
  • Decision: compare the probability with a threshold. Despite its name, logistic regression is a classifier.
P(late | x) = σ(z) = 1 / (1 + e⁻ᶻ)

Changing the threshold changes the decision, without changing the fitted probabilities. Training usually minimizes log loss, not squared error.

K-nearest neighbors (KNN)

Classification / regression
  • Find neighbors: keep the training examples and locate the K closest to the new point.
  • Predict: use a majority vote for classification or average targets for regression.
  • Non-parametric: the model is not restricted to a fixed-size parameterized form.

Small K follows local detail; larger K smooths the vote. Tune K with validation. Distance depends on feature scaling. Circles mark “on time,” squares mark “late,” and the gold diamond is the query.

Support vector machines (SVM)

Classification / regression variant
  • Boundary: separate the classes with a wide margin.
  • Support vectors: the training points that most influence that boundary.
  • Soft margin: allow violations rather than force perfect separation.

Decision boundaries, margins, and support vectors

The solid line makes the decision. Dashed lines mark the margin. Rings identify points touching the margin in this separable example.

A kernel can represent nonlinear boundaries. The regularization setting C controls the penalty for margin violations. Support vector regression uses a related idea for numeric targets.

“Separate the classes” is not enough: the margin helps distinguish possible boundaries. Feature scaling matters here, too.

Naive Bayes classification

Classification
  • Start: use a class prior, then combine evidence from words.
  • Assume: features are conditionally independent given the class.
  • In practice: words often violate this assumption, but the classifier can still be useful.

Select observed words:

Toy probabilities: P(spam) = .30; P(free | spam) = .70, P(free | not spam) = .10; P(meeting | spam) = .05, P(meeting | not spam) = .60. Only selected words contribute; absence is ignored.

P(class | words) ∝ P(class) × ∏ P(word | class)

Normalize the two class scores so they sum to 1. The independence assumption concerns words within a class, not words in the whole dataset.

Decision trees

Classification / regression
  • Split: ask questions that partition the feature space.
  • Learn: choose splits that improve class purity or reduce numeric prediction error.
  • Predict: a leaf gives a class, a class probability, or a numeric value.

A hand-built example to show traversal. A trained tree would learn its questions from data.

A deep tree can memorize small groups of training examples. Depth limits and minimum leaf sizes help control overfitting. Trees usually do not need numeric feature scaling.

Ensemble methods

Classification / regression
  • Ensemble: combine the predictions of several models.
  • Bagging: train models on resampled data and combine their predictions.
  • Random forest: also consider random feature subsets at tree splits, helping make errors less alike.

Boosting: sequential error correction

  • Boosting: add models sequentially to address errors left by the ensemble.
  • AdaBoost: increase attention to misclassified examples.
  • Gradient boosting: fit successive corrections to a loss.

Averaging helps most when models make different errors. Boosting also needs control over complexity.

The figure averages class probabilities, as a forest classifier commonly does. Other ensembles combine votes or weighted scores.

Neural networks and deep learning

Many kinds of tasks
  • Layer: compute weighted combinations of inputs, then apply an activation function.
  • Hidden layers: learn intermediate representations; multiple hidden layers make the network deep.
  • Training: adjust weights through backpropagation and an optimizer.

Hidden layers and learned representations

In images, early layers may detect edges, while later layers combine them into more useful patterns. These features are learned from a training objective rather than individually specified.

The output and loss depend on the task: a numeric value for regression, class probabilities for classification, or other structures for other tasks.

A perceptron is a basic linear classifier. Nonlinear activations between layers let a network represent relationships that a stack of purely linear layers cannot.

06 / Unsupervised learning

Unsupervised learning and clustering

  • Classification: learn to predict known target classes.
  • Clustering: group examples by similarity, without target labels.
  • Interpretation: a discovered cluster is not automatically a meaningful real-world category.

K-means clustering: assignment and centroid updates

Step through the algorithm
circles: examplescrosses: centroids

Assign: give each point to its nearest centroid.
Update: move each centroid to the mean of its assigned points.
Repeat until assignments stop changing.

K-means minimizes within-cluster squared Euclidean distances. Choose K beforehand; try multiple initializations. It is sensitive to scale, outliers, and starting centers, and it works best with compact groups. Here, both axes are already on comparable scales.

Hierarchical clustering and linkage criteria

One dataset, three linkages
  • Agglomerative: start with one cluster per point and repeatedly merge the closest pair.
  • Dendrogram: record the merges; height shows merge distance.
  • Divisive: start with one large cluster and split it.
  • Agglomerative works bottom-up; divisive works top-down.
K has different jobs. In KNN, K counts labeled neighbors used for a prediction. In K-means, K counts unlabeled groups we ask the algorithm to form.
